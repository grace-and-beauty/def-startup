## Що вже працює

- **Власник:** вхід по email (magic link) → майстер онбордингу (ніша → назва/slug → логотип і кольори → правило → PIN) → кабінет: головна з цифрами, аналітика (на Базовій — розмите превʼю), клієнти, розсилки, працівники, постер для друку, налаштування, тариф.
- **Клієнт закладу:** `/c/[slug]` → приєднання → веб-картка `/card/[token]` зі штампами, QR і останнім повідомленням закладу; кнопка Google Wallet зʼявляється, коли задані ключі Google.
- **Працівник:** `/scan/[slug]` → PIN (блокування після невдалих спроб) → сканер QR або ручний ввід → «+1 штамп» / «Видати винагороду», кулдаун між штампами.
- **Тарифи:** тріал 30 днів Плюс → Базова; ліміти клієнтів, розсилок і працівників перевіряються на сервері; неактивний заклад не видає нових карток.
- **Google Wallet:** провайдер з підписаним save-лінком, оновленням картки і повідомленнями; без ключів — автоматично вимкнений (noop).
- **Нагадування:** щоденний cron `/api/cron/reminders` (захищений `CRON_SECRET`).
- **База:** 8+ таблиць, RLS (заклади ізольовані один від одного), захист полів тарифу від зміни власником, транзакційні штампи без дублювання.

## Обмеження / не зроблено

1. **Реальний телефон** — основний сценарій (картка клієнта, сканер камерою, штамп) пройдено вручну з телефона через тунель 4 жовтня 2026. Друк постера на папері ще не перевірявся.
2. **Google Wallet не перевірено з реальним API** — потрібні ключі issuer-акаунта.
3. **Логотипи** — завантаження в Supabase Storage не перевірене (локально Storage немає).
4. **Міграції** перевірені на звичайному Postgres 16, не на Supabase — при першому `supabase db push` уважно подивись на помилки.
5. ~~Зміна PIN не розлогінює працівників~~ — виправлено: сесія сканера прив'язана до PIN. Нові PIN — 6 цифр.
6. Поза MVP: Apple Wallet, онлайн-оплата, звіт у Telegram, модулі «Про», EN/PL, бренд і дизайн.

## Як запустити локально

1. `npm install`
2. Створи проєкт у [Supabase](https://supabase.com) (регіон EU), скопіюй `.env.example` → `.env.local` і заповни ключі Supabase + згенеруй секрети (`openssl rand -hex 32`) для `STAFF_SESSION_SECRET`, `IP_HASH_SECRET`, `CRON_SECRET`.
3. Застосуй міграції: `npx supabase link` → `npx supabase db push`; за бажанням — `supabase/seed.sql` у SQL Editor (демо «Автомийка Демо», PIN `1234`).
4. Supabase → Authentication → URL Configuration: Site URL `http://localhost:3000`, Redirect URL `http://localhost:3000/auth/callback`.
5. Supabase → Storage: bucket `logos` (public).
6. `npm run dev` → http://localhost:3000

Детальніше — `README.md`.

## Що створити вручну перед запуском

| Сервіс | Що зробити |

| Vercel | Імпорт репозиторію з GitHub, env-змінні з `.env.example`, тариф Pro для комерційного використання (cron уже в `vercel.json`) |
| Google Wallet | Issuer-акаунт у Pay & Wallet Console, сервісний акаунт з ключем → `GOOGLE_WALLET_*`, запит на publishing access |
| Apple Developer | Після MVP ($99/рік) |

## Наступні кроки

1. Запустити локально й пройти сценарій з телефона.
2. Назва, бренд і дизайн (рев'ю безпеки й E2E готові: `npm run check` запускає все разом).
3. Задеплоїти на Vercel + Supabase, підключити Google Wallet.
